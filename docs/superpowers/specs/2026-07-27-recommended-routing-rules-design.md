# 推荐分流规则设计

## 目标

将代理页现有的“推荐分流”从三条基础规则扩展为适合国内日常网络环境的默认规则集。默认策略为国内与局域网直连、广告域名拒绝、其余流量代理，并保持规则顺序清晰、行为可预测。

## 范围

- 完善现有“推荐分流”按钮，不新增远程规则订阅。
- 点击按钮后先提示将覆盖现有规则，用户确认后再替换。
- 使用现有 `TrafficRule`、`RuleMatcher` 和 `RuleAction` 模型。
- 保留配置生成器自动追加的 `MATCH,PROXY` 兜底规则。
- 不修改用户手工添加规则的编辑能力。

## 推荐规则

规则严格按以下顺序生成：

1. `DOMAIN,localhost,DIRECT`
2. `DOMAIN-SUFFIX,lan,DIRECT`
3. `DOMAIN-SUFFIX,home.arpa,DIRECT`
4. `IP-CIDR,127.0.0.0/8,DIRECT`
5. `IP-CIDR,10.0.0.0/8,DIRECT`
6. `IP-CIDR,172.16.0.0/12,DIRECT`
7. `IP-CIDR,192.168.0.0/16,DIRECT`
8. `IP-CIDR,169.254.0.0/16,DIRECT`
9. `GEOSITE,category-ads-all,REJECT`
10. `GEOSITE,cn,DIRECT`
11. `GEOIP,CN,DIRECT`
12. `QUIC,REJECT`
13. `MATCH,PROXY`，由现有 Mihomo 配置生成逻辑自动追加。

私网规则放在 Geo 规则之前，确保本地设备、路由器和局域网服务不会依赖 Geo 数据。广告规则放在国内域名规则之前，避免国内广告域名被 `GEOSITE,cn,DIRECT` 提前命中。QUIC 默认拒绝，促使支持回退的客户端使用受现有代理规则控制的 TCP/HTTPS；无法回退的 QUIC 应用可由用户删除该规则。

## 交互设计

- 按钮名称保持“推荐分流”。
- 按钮附近增加简短说明：“覆盖为国内直连、广告拒绝、其余代理”。
- 点击按钮后显示确认对话框，明确提示现有规则将被覆盖。
- 用户取消时不修改内存配置，也不触发保存。
- 用户确认后一次性替换规则并调用现有配置保存流程。
- 保存失败时沿用现有错误状态提示，不保留一半更新的规则。

## 代码边界

- 在代理配置模块提供构建推荐规则集的纯函数，避免 GUI 内硬编码规则列表。
- GUI 只负责显示确认状态、调用规则构建函数和保存配置。
- Mihomo 配置生成逻辑继续负责逐条校验、保持顺序和追加兜底规则。

## 测试

- 验证推荐规则数量、匹配器、动作和顺序完全一致。
- 验证广告规则早于 `GEOSITE,cn`。
- 验证配置生成后最后一条为 `MATCH,PROXY`。
- 验证 Geo 规则会触发现有 Geo 数据路径配置。
- 运行 `cargo fmt`、`cargo check --offline` 和 `cargo test --offline`。
- 桌面验证确认对话框、取消行为、覆盖行为和规则列表显示。

## 非目标

- 不引入远程 Rule Provider。
- 不下载第三方广告规则列表。
- 不增加 IPv6 CIDR 匹配器；IPv6 私网规则留待模型支持 `IP-CIDR6` 后补充。
- 不自动迁移或覆盖用户已保存的规则；只有用户主动点击并确认时才应用。
