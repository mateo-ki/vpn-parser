# 代理控制台 UI 设计

## 目标

把桌面应用从深色卡片式管理页改造成浅色、高密度的网络控制台。代理运行是应用默认首页和侧栏第一菜单，用户进入应用后应立即看见当前出口、接管模式、连通性和主要操作。

## 视觉方向

采用方案 A“浅色网络控制台”。

- 主工作区使用冷白和浅灰，保持长时间阅读舒适。
- 侧栏使用中性石墨色，提供稳定导航锚点，不以深蓝作为主色。
- 主强调色使用青绿色，表示连接、主要操作和选中状态。
- 成功使用绿色，警告使用琥珀色，失败使用红色；状态色只用于有语义的反馈。
- 卡片圆角不超过 6px，去掉大面积悬浮卡片和嵌套卡片。
- 字体尺寸保持桌面工具密度，不使用夸张标题或随窗口宽度缩放字号。

## 导航

侧栏顺序固定为：

1. 代理运行
2. 节点列表
3. 订阅源管理
4. 定时 / 测速
5. HTTP API

应用启动时默认进入“代理运行”。当前菜单使用浅色反差块和青绿色强调，其他菜单保持低对比。菜单图标使用简洁符号，不使用彩色 Emoji。

## 代理首页

页面顶部是无外层卡片的状态标题栏：左侧显示“代理控制台”，右侧显示运行状态。

首行使用两列固定布局：

- 左侧宽列显示当前节点、协议/国家信息和启动、停止、切换节点操作。
- 右侧窄列显示系统代理/TUN 模式、Mixed 端口和控制端口。

第二行显示三个紧凑指标：节点延迟、Google 连通性、当前 DNS。指标使用稳定尺寸，不随文本变化导致布局跳动。

下方使用页内标签切换：

- 分流规则
- DNS / TUN
- 内核
- 日志

规则列表采用表格行，不再为每条规则创建卡片。新增规则控件位于列表下方，保存操作固定在配置区域底部。

## 状态与错误

- `running`：绿色状态点和“运行中”。
- `starting` / `stopping`：琥珀色状态点和旋转指示。
- `failed`：红色状态点，直接展示可执行的错误原因。
- `stopped`：中性灰色状态点。
- 启动前 Google 连通性验证期间显示“正在验证节点”，不提前显示运行成功。
- 失败节点不会启用系统代理，错误区域提示重新测速或切换节点。

## 全局一致性

订阅、节点、设置和 API 页面继续保留现有功能，但统一使用浅色背景、分隔线、紧凑表格和同一按钮层级。状态栏改为浅色底部信息条。原有深蓝背景、发光蓝色按钮、彩色 Emoji 导航和重复卡片边框全部移除。

## 验证

1. 代理运行位于第一菜单且为默认页。
2. 960x600 最小窗口内无重叠、截断或横向溢出。
3. 代理启动、停止、节点切换、规则编辑、DNS 设置、内核信息和日志仍可操作。
4. 运行、停止、失败和过渡状态视觉可区分。
5. `cargo fmt`、`cargo check --offline`、`cargo test --offline` 和 `cargo build --offline` 通过。
