# 测速与运行内核一致性设计

## 目标

确保节点被标记为“可用”时，验证路径与实际代理启动路径一致，消除单节点 TCP 测速误判和 UDP 协议被 TCP 预筛误杀的问题。

## 现状问题

- “测速本页/全部”会先做 TCP 预筛，再通过 Mihomo 完成真实代理访问测试。
- 节点行内的单节点“测速”只连接服务器 TCP 端口，不进行代理握手。
- Hysteria、TUIC、WireGuard 等 UDP 节点可能因 TCP 失败而被跳过。
- 批量真实测速固定使用 Mihomo，无法代表 Sing-box 实际运行兼容性。
- `latency_ok` 没有记录测试使用的内核，旧结果可能与当前自动选择结果不一致。

## 测速语义

- “可用”表示所选运行内核成功建立代理并访问 `https://www.google.com/generate_204`。
- “不可用”表示所选运行内核配置不支持、启动失败、代理握手失败或测试地址访问失败。
- “未测速”表示没有真实代理验证结果。
- TCP 预筛只用于减少批量验证成本，不作为最终可用结论。

## 行为设计

- 单节点测速复用批量真实验证管线，不再直接调用 TCP-only `test_one` 逻辑。
- 批量测速先根据自动内核选择器分组，再分别交给 Mihomo 和 Sing-box 探测器。
- TCP 类协议执行 TCP 预筛；`hysteria`、`hysteria2`、`hy2`、`tuic`、`wireguard`、`wg` 跳过 TCP 预筛。
- 探测结果记录实际内核；重新测速时覆盖旧结果。
- 启动代理前仍执行运行内核健康检查，处理节点在测速后临时失效的情况。
- UI 明确显示“真实代理测速”，不再把 TCP 预筛结果展示为最终可用。

## 数据设计

在节点表增加可空字段：

- `latency_kernel`：`mihomo` 或 `sing_box`。
- `latency_test_kind`：新结果写入 `real_proxy`；历史 TCP-only 结果迁移为 `tcp_only` 或空值。

只有 `latency_ok = 1` 且 `latency_test_kind = real_proxy` 才计入真实可用统计。

## 测试

- 单节点测速调用真实代理验证。
- WireGuard 和其他 UDP 协议绕过 TCP 预筛。
- 节点按自动选择结果进入正确内核组。
- 结果持久化内核和测试类型。
- 启动健康检查失败不会保留“当前运行中”状态。

## 非目标

- 不同时使用两个内核竞速同一节点。
- 不以 TCP 可连接作为最终可用状态。
- 不取消启动阶段的二次健康检查。
